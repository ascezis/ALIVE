# Данные и PDF

## SQLite

В контейнерах файл базы по умолчанию расположен в `/data/lfk.sqlite3`. Каталог `/data` монтируется с хоста. Локально по умолчанию используется `backend/data/lfk.sqlite3`. Путь переопределяется через `ALIVE_DATABASE`.

| Таблица | Что хранится |
| --- | --- |
| `alive_workout_state` | По одной строке на профиль. Первичный ключ `owner`, номер `revision` и `state_json` |
| `alive_reminder_delivery` | Состояние отправки, число попыток и время следующей попытки. Ключ состоит из владельца, локальной даты и слота `morning` или `evening` |
| `alive_reminder_override` | Разовый перенос вечернего времени для владельца. Применяется только к указанной локальной дате |
| `alive_wakeup_timer` | Один активный или ожидающий подтверждения таймер WAKE UP на владельца |
| `alive_wakeup_breaks` | Подтверждённые перерывы с временем нажатия в Unix-секундах и локальной датой. Ключ из владельца и идентификатора таймера предотвращает дубли |
| `lfk_imports`, `lfk_exercises`, `lfk_programs`, `lfk_program_exercises` | Версии справочника и шаги программ. Появляются после импорта каталога |

Профиль в Telegram имеет ключ `telegram:<id>`. Локальная разработка использует отдельный ключ `local`. Таблицы рабочего состояния создаются по мере обращения, включая запуск на пустой базе.

`state_json` содержит `session` (активный комплекс, снимок программы, шаги и время), `timer`, `summary` (итог, ожидающий сохранения) и `diary` (записи по датам `YYYY-MM-DD`). За один день можно записать несколько занятий. Для самочувствия хранятся боль и утомляемость по шкале 0–10, а также утренняя скованность в минутах. `null` означает отсутствие отметки. `0` — сохранённое значение. У занятия сохраняются тип и название, длительность, результаты шагов, названия упражнений или ID видео, а также заметка до 500 символов.

## API и запись из чата

| Маршрут | Назначение |
| --- | --- |
| `GET /api/state` | Прочитать сохранённый снимок, его номер ревизии и дневную цель ЛФК |
| `PUT /api/state` | Сохранить валидированный снимок с исходным номером ревизии |
| `POST /api/report` | Сформировать PDF за включительный диапазон дат `start` и `end` |
| `GET /api/report/download/{token}` | Скачать готовый PDF. `HEAD` отдаёт метаданные для загрузчика |

Mini App передаёт `revision` вместе с изменениями. API сравнивает её внутри транзакции. При расхождении возвращается `409`, приложение предлагает обновить страницу. Повтор идентичного снимка возвращает текущую ревизию. Бот в транзакции читает последнюю версию, меняет одно поле выбранного дня и увеличивает ревизию только при фактическом изменении. Другие поля дня, тренировки и текущая сессия сохраняются.

Сервер проверяет подпись и возраст Telegram `initData` из заголовка `X-Telegram-Init-Data` и разрешает доступ только заданному ID. Воркер сверяет ID отправителя и личного чата. Все ответы API идут с `Cache-Control: no-store`. В браузерном демо используется отдельное состояние в памяти вкладки, без чтения реальных записей.

## PDF для ревматолога

Отчёт собирается на сервере через ReportLab с кириллическими шрифтами. В нём отображаются охват периода, динамика боли и утренней скованности, график утомляемости при наличии отметок, дни с занятиями и приложение с записями и заметками. Сплошная линия соединяет соседние дни с отметками. Пунктир показывает разрыв между известными точками, без добавления значений на пропущенные дни. Отчёт включает сохранённые занятия.

Создание требует авторизации. PDF остаётся в памяти API. Случайный токен в ссылке даёт доступ к файлу в течение 180 секунд. Ссылка доступна любому, у кого есть токен в пределах срока действия, поэтому её следует считать приватной. Хранилище содержит до 16 готовых отчётов и очищается при перезапуске API. Для передачи врачу используется скачанный PDF.

## Каталог упражнений

Скрипт [backend/import_lfk.py](../backend/import_lfk.py) переносит справочник из JSON в SQLite и сохраняет его ревизии. Импорт идемпотентен по содержимому и выполняется одной транзакцией. Он относится к каталогу упражнений. Дневник обслуживает `alive_workout_state`.

```sh
python backend/import_lfk.py --source src/lfk-spec.json --database backend/data/lfk.sqlite3
```

Пример запроса шагов программы из последней версии справочника.

```sql
SELECT step.position, exercise.exercise_id, exercise.title,
       json_extract(exercise.exercise_json, '$.dose') AS dose,
       step.advisory
FROM lfk_program_exercises AS step
JOIN lfk_exercises AS exercise USING (import_id, exercise_id)
WHERE step.import_id = (SELECT MAX(id) FROM lfk_imports)
  AND step.program_id = 'morning_mobility_posture'
  AND step.program_version = '0.1'
ORDER BY step.position;
```
